# ADR-0002: アプリ名リネームの段階設計（表示名と内部識別子の分離）

- ステータス: Accepted（2026-05-25・Issue #214）
- 関連: ADR-0001 / インフラ構成.md / CLAUDE.md §1（リポジトリ名）

## 背景

アプリの**表示名**を「レビューラボ」に変更したい（ロゴも柴犬→水色のイルカ）。一方で、
コードベース・基盤には `review-board` / `com.reviewboard` 由来の**内部識別子**が広く存在する。

本番（S-2）は AWS 上で稼働中であり、内部識別子まで一度に変えると CD / デプロイ / AWS 資源 /
Flyway / DB を壊すリスクが高い。表示名の変更にこれらは不要。そこで**2層に分離**する。

## 決定

### 第1層：表示名（今回実施・低リスク）
ユーザーに見える名前のみを「レビューラボ」に変更し、**単一ソース化**する（将来の改名は1〜2箇所）。

- frontend: `src/constants.js` の `APP_NAME` / `APP_TAGLINE` を唯一の真実とし、Header / LoginPage /
  RegisterPage / PostsPage / `document.title`（App.jsx）が参照する。`index.html` の `<title>` は
  初期表示用フォールバック（実行時に App が上書き）。
- backend: `app.name`（application.yml・env `APP_NAME` で上書き可）を `NotificationService` の
  メール署名に注入。

→ 表示名の再変更は **frontend `constants.js` 1行 ＋ backend `app.name` 1行**で完結する。

### 第2層：内部識別子（将来・大規模・本ADRはその「地図」）
完全リネーム（例：`reviewlab` への統一）を行う場合の影響範囲と安全な順序。**本番影響が大きいため
独立した PR 群で、各々 plan→人間承認→apply の順に慎重に進める**（CLAUDE.md §6/§12）。

| 領域 | 識別子（現在） | 影響・注意 |
|---|---|---|
| Java package | `com.reviewboard.*` | 全クラス移動＋import 一括置換。`ReviewBoardApplication` 名。リスク中（機械的）。 |
| ビルド成果物 | jar 名・`spring.application.name=review-board` | ログ/メトリクスのラベルが変わる。 |
| フロント | `package.json` name `review-board-frontend` | 表示には無関係。 |
| リポジトリ/フォルダ | repo `hideharu-AI`・ディレクトリ `review-board/` | CI の `paths:` フィルタ・各種相対パス・CLAUDE.md の記述を追従。 |
| CI ワークフロー | `review-board-*.yml`・job/notice 文言 | 名前変更だけなら低リスク。 |
| AWS 資源 | `review-board-prod-*`（EC2 tag Project=review-board・S3 ×2・IAM ユーザー・SSM プレフィックス `/review-board/prod`） | **最重要・最危険**。S3 バケットは改名＝作り直し（データ移行要）。SSM プレフィックス変更は provision.sh / deploy.sh / cd-deploy の参照を同時更新。EC2 tag を変えると cd-deploy のインスタンス解決条件が変わる。Terraform の rename は state mv or 再作成の判断が要る。 |
| Flyway | migration の comment 等 | スキーマ名は不変なら影響なし。 |
| メールドメイン | `no-reply@review-board.local` | 正規ドメイン取得時に併せて変更。 |

#### 推奨順序（将来）
1. CI 文言・`package.json`・`spring.application.name` など**無害なラベル**から。
2. Java package（機械的置換＋全テスト green 確認）。
3. リポジトリ/フォルダ名（CI `paths:` と相対パスを同時更新）。
4. AWS 資源は**最後**。S3 はデータ移行を伴うため、新バケット作成→同期→切替→旧削除を人間承認で。
   SSM プレフィックス・EC2 tag・cd-deploy 条件は一括で整合させる。

## 結果
- 今回は第1層のみ。表示名「レビューラボ」＋イルカロゴが本番に出せる。内部は無変更で CD/AWS に影響なし。
- 第2層は本ADRを地図として、必要になった時点で独立タスク化する（やるとは限らない）。
