## 1. テスト方針（ピラミッド型）

```
        ▲  E2E（少）       … 主要導線のみ（出題→採点→次へ）
       ◢◣
      ◢──◣ 結合（中）      … フック＋api/層（useQuiz × localStorageRepository）
    ◢──────◣ ユニット（多） … 純粋ロジック（shuffle / 採点 / Progress堅牢化）
```

- ロジックの**単体テストを土台**に厚く、E2Eは主要導線に絞る（M-7）。
- UIを伴う変更は**実ブラウザで確認**する（M-13・テスト緑≠UIが動く）。

## 2. 現状の検証手段（実装済み）

| 手段 | 内容 | 対応 |
|---|---|---|
| **CI（GitHub Actions）** | `npm run build`（型チェック＋ビルド）＋`npm audit --audit-level=high` を PR/main で実行 | 受入 A-6・M-6 |
| **実ブラウザ検証** | Chrome DevTools で出題→採点→解説→進捗保存→graceful degradation を確認 | M-13・受入 A-1〜A-4 |
| **Lighthouse（モバイル）** | Accessibility=100 / Best Practices=100 / SEO=100、LCP 92ms・CLS 0.00 | 受入 A-5・重点軸 |

> 現状は**自動テストコード（ユニット/E2E）が未導入**で、上記で品質を担保している。これは小規模MVPでの
> 意図的な段階判断であり、機能が増える前に §3 の自動テストを導入する。

## 3. 導入予定の自動テスト（計画）

### 3-1. ユニットテスト（優先・次の整備対象）
- ツール候補：**Vitest**（Vite と統合・高速）。
- 対象：
  - `utils/shuffle.ts` … 全要素保持・非破壊・（統計的に）位置が散ること（F-QUIZ-03/A-2）
  - `hooks/useQuiz.ts` … 採点ロジック・進捗更新・分野フィルタ・連続同一用語の回避
  - `api/localStorageTermRepository.ts` … **破損データで初期化して継続**（A-4）・保存失敗時の継続

### 3-2. 結合テスト
- `useQuiz` × `localStorageTermRepository` を React Testing Library で結合し、回答→Progress保存→再読込を検証。

### 3-3. E2E（主要導線のみ）
- ツール候補：**Playwright**。
- シナリオ：出題→選択→採点表示→「次の問題」→別用語、分野フィルタ切替、リロードで進捗維持。

### 3-4. CI への組み込み（計画）
- `term-board-ci.yml` に `npm run test`（Vitest）を追加し **lint→build→test** の Fail Fast に拡張。
- E2E は別ジョブ（他アプリの e2e.yml に倣う）。
