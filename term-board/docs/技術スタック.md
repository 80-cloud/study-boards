## 1. 全体構成

```
┌─────────────────────────────────────────────┐
│  ブラウザ（利用者の端末）                      │
│  ┌───────────────────────────────────────┐  │
│  │ React 19 SPA（Vite + TypeScript）       │  │
│  │  components/（表示） hooks/（学習ロジック）│  │
│  │  api/（隔離層）──┐                       │  │
│  └─────────────────┼───────────────────────┘  │
│         localStorage（進捗）  src/data/terms.json│
└─────────────────────────────────────────────┘
              ▲ 静的ファイル配信のみ
┌─────────────┴───────────────────────────────┐
│  GitHub Pages（静的ホスティング・無料）         │
│  ← GitHub Actions が main push でビルド&デプロイ │
└─────────────────────────────────────────────┘
```

サーバー・DB・APIは存在しない。採点・進捗保存はすべてブラウザ内で完結する（ローカル即時判定＝重点軸の根拠）。

## 2. 採用技術一覧

| レイヤ | 技術 | 版 | 選定理由 |
|---|---|---|---|
| 言語 | TypeScript | ^5.7 | 型安全（M-12）。用語・進捗の型を保証 |
| UIライブラリ | React | ^19 | コンポーネント設計・フックの学習対象（要件定義書 §1-2） |
| ビルド | Vite | ^6 | 高速なdev/build。`base` でサブパス配信に対応 |
| スタイル | Tailwind CSS | ^4（@tailwindcss/vite） | ユーティリティで素早くWCAG AA配色を実装 |
| 永続化 | localStorage | — | サーバーを持たないMVPの進捗保存（C-1）。`api/` 層で隔離 |
| 用語データ | 静的JSON（`src/data/terms.json`） | — | 同梱・動的更新なし（C-2） |
| ランタイム | Node.js | **24 LTS**（`.nvmrc`） | 奇数版（25）＝非LTSを避けビルド再現性を確保 |
| ホスティング | GitHub Pages | — | 静的配信・無料・誰でもURLで利用可（認証不要） |
| CI | GitHub Actions | — | 型チェック＋ビルド＋`npm audit`（受入 A-6） |

## 3. ディレクトリ構成と責任分離（M-3）

```
src/
├── api/            # データ取得・保存の隔離層（差し替え点は index.ts の1箇所）
│   ├── termRepository.ts          # インタフェース
│   ├── localStorageTermRepository.ts  # MVP実装
│   └── index.ts                   # ← Phase4で http実装に差し替えるだけ
├── hooks/          # 学習ロジック（useQuiz）
├── components/     # 表示（QuizView / CategoryFilter）
├── data/terms.json # 用語データ
├── utils/          # 純粋関数（shuffle）
└── types.ts        # Term / Progress 型
```

## 4. 採用しない技術と理由（過剰機能を持たない＝品質低下リスク回避）

| 技術 | 不採用の理由 | 将来 |
|---|---|---|
| Spring Boot / サーバー | 学習アプリはサーバー判定が不要（ローカル即時判定で十分） | Phase 4 で `api/` 差し替え |
| PostgreSQL / DB | 単一利用者・他人とデータ共有しない | Phase 4 |
| 認証（JWT等） | ログイン不要が前提。持つと攻撃面が増える | Phase 4（F-AUTH-01） |
| AWS / Terraform | 静的配信に重厚なインフラは不要。GitHub Pages で足りる | Phase 4 |
| 状態管理ライブラリ（Redux等） | 規模が小さく、フック＋Contextで十分 | 必要時に検討 |

> Phase 4（多人数化）の判断条件は要件定義書 §12 で明文化予定。`api/` 隔離により**作り直しゼロ**で移行できる。

## 5. バージョン整合の方針

要件定義書 §2 C-6 に従い、実機ランタイムと build toolchain を一致させる（`.nvmrc`=24）。
Phase 4 でバックエンドを足す場合は Java 25 / Gradle 9.1 / Spring Boot 3.5.x（他アプリと統一）を採用する。
