## 1. 全体像（3系統・疎結合）

```
  ┌──────────────┐        ┌──────────────────┐      ┌──────────────────┐
  │ Term（用語）  │ termId │ Progress（実力）   │      │ LearningLog（軌跡）│
  │ 静的JSON同梱  │◀──────▶│ localStorage      │      │ localStorage（将来）│
  └──────────────┘        └──────────────────┘      └──────────────────┘
        ▲ 1用語→3モード導出          ▲ 用語IDで結合              ▲ 同じ解答イベントから別の見せ方
```

- **Term と Progress を分離**：用語IDで結合するため、用語の追加・修正が進捗を壊さない。
- **Progress（実力）と LearningLog（軌跡）を分離**：同じ解答イベントから別の見せ方を作る（実装は Phase 3）。

## 2. Term（用語）— 1件から3モードを導出（DRY）

| フィールド | 型 | 必須 | 用途 | 使う機能 |
|---|---|---|---|---|
| `id` | string | ✅ | 一意キー（例 `"tcp-ip"`）。Progress との結合キー | 全般 |
| `category` | string | ✅ | 分野（ネットワーク等） | F-TERM-02 / F-QUIZ-04 |
| `term` | string | ✅ | 表示名（例 `"TCP/IP"`） | 4択の問・暗記カード表 |
| `meaning` | string | ✅ | 正しい意味（4択の正解／暗記カード裏） | F-QUIZ-01/02 |
| `distractors` | string[] | ✅ | 4択の誤答。meaning と混ぜてシャッフル | F-QUIZ-01/03 |
| `interview` | string | ✅ | 面接での短い言い方（核＋結論） | F-INTV-01 |
| `plainMeaning` | string? | 任意 | 中学生にも分かる平易な説明 | **F-TERM-05（実装済）** |
| `scene` | string? | 任意 | 現場での使われ方シーン | F-TERM-04（予定） |
| `followUps` | {q;a}[]? | 任意 | 深掘り「なぜ?」チェーン | F-INTV-03（予定） |
| `reverseQuestions` | string[]? | 任意 | 派生する逆質問 | F-INTV-07（予定） |
| `related` | string[]? | 任意 | 関連用語ID（知識マップ） | F-PROG-06（予定） |
| `confusedWith` | string[]? | 任意 | 混同しやすい用語ID | F-QUIZ-06（予定） |
| `source` | "builtin"\|"user"? | 任意 | 出所。同梱=builtin／ユーザー作問=user | F-USER-01 |

> **拡張フィールドは全て任意。** 既存用語は中核フィールドだけで動き、列追加で段階的に機能を増やせる（母 M-11）。

### 3モードの導出
- **4択**：`meaning` + `distractors` をシャッフル（正解位置ランダム化＝F-QUIZ-03）
- **暗記カード**：表 `term` / 裏 `meaning`（+ `plainMeaning`）
- **面接問答**：問「`term` とは？」/ 模範 `interview`（+ 深掘り `followUps`）

## 3. Progress（用語ごとの実力）

```ts
type Progress = {
  [termId: string]: { correct: number; wrong: number; lastAnsweredAt: string };
};
```

- localStorage キー：`term-board:progress:v1`
- 用語IDをキーに正答/誤答回数と最終解答日時を保持（F-PROG-01）。
- **堅牢化**：読み込み時に JSON パース失敗・スキーマ不一致を try/catch でガードし、壊れていれば
  進捗のみ初期化して出題は継続する（graceful degradation・要件定義書 §4-1・受入 A-4）。
- 将来の用途：分野別正答率（F-PROG-02）・苦手抽出（F-PROG-03）・間隔反復（F-QUIZ-05）の入力。

## 4. LearningLog（時系列の学習の軌跡・Phase 3 で実装）

```ts
type LearningSession = { id; startedAt; mode: "quiz"|"card"|"interview"; asked; correct };
type LearningNote    = { id; createdAt; termId?; body };
type LearningLog     = { sessions: LearningSession[]; notes: LearningNote[] };
```

- ストリーク／カレンダー（F-LOG-02）は `sessions[].startedAt` を**表示時に集計して導出**し、保存しない。
- `notes.body` はプレーンテキスト保存（XSS非該当・母 SEC-5）。

## 5. InterviewQuestion / UserContent（ユーザー作問・F-USER）

ユーザー（経験者＝講師役）が自分で書く「実際に聞かれた面接質問」と、共有・保存の単位。

```ts
type InterviewQuestion = {
  id: string;
  category: string;   // 分野・場面（例 "自己PR" "技術" "逆質問"）
  question: string;   // 実際に聞かれた質問
  answer: string;     // 模範回答／自分の答え
  memo?: string;      // 補足（聞かれた状況・コツ）
  source?: "builtin" | "user";
};

type UserContent = {
  quizTerms: Term[];                 // ユーザー作問の4択用語
  interviewQuestions: InterviewQuestion[]; // ユーザー作問の面接Q&A
};
```

- localStorage キー：`term-board:userContent:v1`。破損時は空で返し builtin 出題を継続（A-4）。
- `getTerms()` は **builtin ＋ user の quizTerms を統合**して返すため、作問した4択用語は即クイズに出る。
- **共有（F-USER-02）**：`UserContent` を JSON 化して base64 の「共有コード」にし、Discord 等で配布。
  取り込み時はIDを振り直して衝突を避け、既存に追記する（サーバー無しのピア共有）。
